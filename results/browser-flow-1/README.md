浏览器发现两处实际故障并完成回验：

1. 优先动作统计包含强制问题，但固定跳到空的否决分类。修复入口按当前报告选择有待处理问题的否决或强制分类，解析后固定 URL；本例进入 `category=response`，显示实际的 240／180 天冲突。登记前风险检查使用同一入口，确认问题后仍在当前分类。原故障证据为 `wrong-priority-destination.*`，修复为 `priority-fixed.*` 与 `submit-priority-fixed.jpg`。
2. 规则确认后，登记页从评审时的冻结矩阵计算待确认数，错误提示仍有 1 条。修复改用服务端按当前有效规则计算的 `confirm_rules.count`，保留冻结矩阵及历史依据状态；本例最终规则检查通过，真实的强制问题仍阻止登记，没有登记提交或虚构官方成绩。
