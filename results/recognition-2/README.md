# 混合解析身份恢复、索引回填与核验规模

产品运行版本 `ed8ce80`，数据库迁移 0007。验证只修改随机命名的独立临时库，业务库只读备份；正常 Word 服务保留，Claude 已关闭的测试容器未启动。默认 keyword 与业务部署保持。

## 混合身份恢复

`scripts/mixed_identity_restore_check.py` 将业务备份恢复到临时库，复用 `recognition-1` 的真实合成表格解析和两条人工核验记录，在副本复制合成招标资料、建立合成规则包，调用正式 `snapshots.freeze_inputs` 建立 input-v2。再次备份并恢复到另一临时库，逐表按稳定排序序列化全部行并计算 SHA-256。

- 47 张表、981 行的内容与行数完全一致。
- 7 份旧快照未补写身份，1 份新快照的解析、证据集合、覆盖缺口和 manifest 保持。
- 2 条核验记录、8 对完整证据映射保持；source/result 均属于原项目、文件版本及相应解析。
- 快照、解析、证据、核验记录的更新被只追加触发器拒绝；API 与 worker 角色均可读取核验记录，无未验证约束。
- 业务备份 253,616 字节，SHA-256 `644b1eb640302fb8991a8f914d7dc4b4895f532450d75fc1814feff2bbc1471c`。
- 混合副本备份 253,085 字节，SHA-256 `2fba078eae4a58cc156a9e3dd3e3edd3c410d78029fe580b15e2ce139b5302a6`。

两个 dump 均在工作区本地 `codex-diagnostics/`，不提交数据库备份。清单使用测试内存对象存储，恢复后仍保留该对象，只验证恢复的数据库引用与原清单相符；未恢复 OSS 或原属主，不是完整灾难恢复。

## 索引与核验规模

`scripts/recognition_index_scale_check.py` 将混合副本恢复到独立 pgvector 库，复用本机固定 BGE ONNX 模型及只读后端镜像，分别以 app_api／app_worker 角色执行正式检索／回填服务。模型指纹为 `b29efd8ae67fc41b0895404ede82fb60ede198a5f58bc34ff57002401ad0b436`。

缺少新 ID 或索引文本摘要损坏时，检索明确回退关键词；16 条证据回填后恢复 hybrid，幂等重跑通过。回填除派生索引外不改任何业务表；当前检索只使用当前解析 ID，正确返回已支持的 `Cost 15.12`。随后追加各规模的合成解析并调用正式核验服务，旧 input-v2 的检索响应保持完全一致。

| 父解析证据数 | 单次核验耗时 | 结果 |
| --- | --- | --- |
| 1,000 | 0.086 秒 | 追加 1,000 条新证据，原候选保持 pending |
| 10,000 | 0.704 秒 | 追加 10,000 条新证据，完整一一映射 |
| 20,000 | 1.399 秒 | 追加 20,000 条新证据，完整一一映射 |
| 20,001 | 不作成功耗时统计 | `recognition_review_too_large`，所有表内容保持 |

耗时为每档一次，包含正式服务、数据库提交和内存对象存储，不含 HTTP、OSS 网络、完整 API 并发或目标主机容量；大规模输入为 SQL 合成，不是 OCR 实测。BGE 只用于小集合真实回填和检索机制验证，不证明语义召回质量。所有临时数据库与测试容器已清理。

完整机器结果见 [mixed-restore-receipt.json](mixed-restore-receipt.json) 与 [index-scale-receipt.json](index-scale-receipt.json)。
