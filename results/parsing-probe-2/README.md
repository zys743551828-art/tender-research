# 续表与旋转图像对照

本轮接续 [首轮探针](../parsing-probe-1/README.md)，针对 CASE-001 正文第 46—48 个物理页检查设备表和劳动力表续页。[参考协议](../../experiments/parsing-probe-2.json)在本轮推理前依据原图填写，没有修改原始 PDF。独立 RapidOCR 另对同样三页的渲染图作顺时针 90° 对照；这是旋转图像控制，不是原件自带旋转元数据的 PDF 测试。

| 输入／引擎 | 有产物页 | 文字锚点 | 本轮耗时 |
| --- | --- | --- | --- |
| 原始 PDF／原生文字 | 3/3 | 11/11 | 0.13 秒 |
| 原始 PDF／MinerU basic | 3/3 | 11/11 | 14.32 秒 |
| 正常页图／RapidOCR | 3/3 | 10/11 | 6.32 秒 |
| 90° 页图／RapidOCR | 3/3 | 10/11 | 5.35 秒 |

锚点、协议 SHA、变换参数和产物 SHA 见 [comparison.json](comparison.json)，它只记录文字锚点，不充当表格、图意或正式预测准确率。两个 OCR 控制都没有完整命中第 46 页的“高压水射流清洗机”；原生文字中已有正确词组，不能用 OCR 覆盖替换原文。版本复用首轮 D 盘环境和模型缓存，没有新增安装。以上耗时不作为生产性能排名。

原图核对表明：第 46 页设备表序号 1—23，第 47 页续 24—26 后开始新表；第 47 页劳动力表有表头和两行数据，第 48 页从推土机司机续表，没有重复表头。MinerU 保留了第 48 页抽查的推土机司机、电工、交通导行员各十个数字，与参考逐格一致；[检查记录](manual-review.json)保存具体数组。该页仍是单独表格，没有继承第 47 页表头或显式续表链接，跨页自动合并尚未实现。局部三行正确不外推为全表正确。

## 产品覆盖修正

产品解析器 `pdfium-1.2` 增加逐物理页的文字状态、图片对象数和未覆盖原因，检查到图片即保留 `raster_images_unread`，包括文字覆盖在图片之上的页面。装饰背景也可能触发 partial，不猜测图片用途。单页 PDFium 读取错误不会中断后续页；旋转页继续保留文字并将证据坐标置空。表格结构和图形语义始终明确为未评价，尚未接入 OCR 或续表合并。

绑定原件哈希的实际解析结果见 [product-coverage.json](product-coverage.json)：原生解析完整读取 50 页正文和 220 页公开文件，分别保留 361 和 1724 个文字证据块。正文图片页和公开文件的扫描收费页均保留 partial，而非因标题或页码误报完整。该文件只摘录正文 46—50 页和公开文件 26 页的页级清单，文档缺口清单完整保留。

完整后端回归 171 项通过；研究回归 167 项通过、2 项 POSIX 权限用例在 Windows 跳过。前端代码未改动。产品产物字段及覆盖边界以 `tender-app/contracts/parsing-artifacts.md` 为准，旧产物与旧快照保留原版本语义，需重新解析才生成新记录。

复跑沿用首轮命令，将协议改为 `experiments/parsing-probe-2.json`；仅 `rapidocr` 或 `paddle` 图像输入支持 `--render-rotation 90`，其余引擎会明确拒绝该参数。原图、旋转图、原始结构及失败记录位于本机 `codex-diagnostics/parsing-extension-20261017/`。下一步继续重要数字单位核对、可追溯 OCR 与表格接入、超时和恢复，以及图形语义验收。
